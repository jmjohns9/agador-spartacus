# Issues noticed during the macOS redesign

Recorded for the code review. Fixed here only where the redesign had to touch the line anyway.

| Where | Issue | Status |
|---|---|---|
| `files/src/renderer/index.html` | `<script src="renderer.bundle.js">` — webpack emits `renderer.js` and HtmlWebpackPlugin injects it; this tag 404s | open |
| `files/src/renderer/index.html` | CSP allows fonts.googleapis.com / fonts.gstatic.com, no longer used after the redesign | removed in cleanup task |
| `files/src/renderer/screens/PcmScreen.tsx:47` | `var(--tp)` was never defined | aliased to `--label` (Task 1), removed in PCM sweep |
| `files/src/renderer/App.tsx` (old) | Connected chip hard-coded "OBDLink MX+" regardless of adapter | fixed by shell (uses `adapterInfo`) |
| `files/src/renderer/App.tsx` (old) | Status-bar selector recomputed on every PID reading | fixed by shell (computed only while popover open) |
| `files/src/renderer/screens/LiveScreen.tsx:11-21` | `usePID()` calls `useAppStore` a second time only inside `if (!reading) return …`, so the number of hook calls per render depends on live-data readiness. Reproduced via CDP: connect the simulator, let a few PID readings land, then trigger any re-render — React throws "Rendered more hooks than during the previous render" and unmounts the screen (crash overlay, recoverable via "Reload renderer"). | fixed in redesign (commit e41e84b) |
| `files/src/main/main.ts` `obd:disconnect` handler (or something it triggers — `stopRSSIPolling()`/`releaseActivePort()`/simulator teardown) | Clicking "Disconnect" on `ConnectionScreen` after connecting via the built-in simulator hangs the renderer's JS thread outright — not a crash, a full freeze: even a trivial CDP `Runtime.evaluate("1+1")` against the page stops responding within ~1s of the click and never recovers (tested up to 40s). Reproduced on both the pre-redesign `ConnectionScreen.tsx` (commit a2b0154, i.e. before Task 8's restyle) and the restyled version — confirmed pre-existing, not introduced by the DTC/Connection screen sweep (Task 8). Repro: `npm run build && electron . --remote-debugging-port=<port>` with `NODE_ENV=production`, click "Launch Emulator" on the Connection screen, wait for `connected`, click "Disconnect". | fixed (fix(main) commit 1fbbbbb — root cause: a pending simulator reply fired after disconnect and threw in the main process, whose uncaught-exception dialog froze the app) |
| `files/src/core/obdProtocolManager.ts` `scanDTCs` / `readVIN` / `clearDTCs` | Each pauses polling and then resumes it if it was running before, ignoring a `stopPolling()` made in the meantime. Disconnecting during a DTC scan or the post-connect VIN read restarted the poll loop on the dead session, so it ran forever (timing out every command, or writing to a closed serial port). | fixed (fix(core) commit d144647) |
| `files/src/main/main.ts` connect / disconnect lifecycle | Async connect chains were not tied to the session that started them. Disconnecting while the simulator was initializing left its init running: ~25 s later it reported `connected` with no session behind it (UI stuck on "Connected", no data). Reconnecting (or pressing Launch Emulator twice) let the old chain start a second OBD manager on the new adapter, whose poll loop disconnect never stopped. A serial attempt that was disconnected or replaced later reported `error` over the running simulator, and the serial port's own `close` event (fired when we release the port after a failed attempt) overwrote the `error` with `disconnected`, so the failure reason never showed. | fixed (fix(main) commit 621d39e) |
| `files/src/main/main.ts` `obd:connect` / `obd:disconnect` (after 621d39e) | `obd:connect` read `sessionGen` only after `await endSession()`. A connect or disconnect that arrived while the old serial port was still closing bumped the generation first, so the earlier handler resumed holding the newer generation. Reproduced over CDP: Launch Emulator then Disconnect while a serial port was open ended `connected` (the Disconnect was silently overridden), and two Launches ended in `error` (two commanders shared one generation; the first was never closed). | fixed (fix(main) commit "let a newer connect/disconnect win over one still closing the port") |
| `files/src/main/main.ts` `startRSSIPolling` | The `system_profiler` call takes seconds; a result landing after `endSession()` cleared the RSSI re-posted a stale non-null value to the renderer. | fixed (fix(main) commit "drop Bluetooth RSSI results that land after the session ended") |
| `files/src/main/main.ts` `startSimulator` | The simulator never reported `connecting`, so for the whole init the UI showed "Disconnected" with Launch Emulator still enabled. | fixed (fix(main) commit "report connecting while the simulator initializes") |
