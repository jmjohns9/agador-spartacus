Connect the bridge to the OBDLink

Tattlestone ↔ Arduino UNO Q ↔ OBDLink MX · the bridge now owns the Bluetooth link · branch fix/bridge-owns-bluetooth-link

What's going on

The app always reached the bridge, but the bridge then tried to open /dev/rfcomm0, and nothing ever created it. That device only appears after a manual root command (rfcomm bind), it disappears at every reboot, and the earlier bind attempt never succeeded:

BRIDGE ERROR: cannot open /dev/rfcomm0: No such file or directory

New design: the bridge opens the Bluetooth link to the OBDLink itself, once per app session, and closes it when the app leaves. There's no /dev/rfcomm0 and no rfcomm commands. The app:

  • shows the bridge's progress while it connects
  • reconnects to the last bridge whenever you open it
  • says what to do when something is missing

One step stays manual, once: pairing the OBDLink with the board (step 2). It needs you at the adapter.

1 Get the truck and adapter ready Truck · Mac

  1. Plug the OBDLink MX into the Silverado's OBD port (under the dash, left of the steering column).
  2. Turn the ignition on. The engine doesn't need to run.
  3. On the Mac, disconnect from the adapter: System Settings → Bluetooth → OBDLinkMX… → ⓘ → Disconnect. The OBDLink accepts one Bluetooth host at a time.
  4. Keep the UNO Q within a few metres of the truck.

2 Pair the board with the OBDLink (once) UNO Q

ssh arduino@192.168.1.33
bluetoothctl

At the [bluetooth]# prompt:

power on
agent on
default-agent
scan on

Wait for a line like [NEW] Device 00:04:3E:12:34:56 OBDLinkMX13659. Type the address from your screen into these (no angle brackets):

scan off
pair 00:04:3E:12:34:56
trust 00:04:3E:12:34:56
quit
  • PIN prompt: 1234 (then 0000). "Authorize service?" / confirm passkey: yes.
  • You don't need to write the address down. The bridge finds the paired OBDLink by name.
Done when you see Pairing successful and trust succeeded. Check with bluetoothctl devices Paired.

3 Deploy the new bridge Mac → UNO Q

From the Mac, on the branch with the fix (or main once its PR is merged):

cd ~/Tattlestone/agador-spartacus
git fetch
git checkout fix/bridge-owns-bluetooth-link
scp files/firmware/uno-q-bridge/obd_tcp_bridge.py files/firmware/uno-q-bridge/tattlestone-bridge.service arduino@192.168.1.33:~/uno-q-bridge/

Then on the board:

getent group bluetooth && echo "bluetooth group OK"
sudo cp ~/uno-q-bridge/tattlestone-bridge.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl restart tattlestone-bridge
journalctl -u tattlestone-bridge -n 5 --no-pager
Done when the journal shows Bridge listening on :35000 -> Bluetooth auto channel 1.
If getent printed nothing, the board has no bluetooth group and the service won't start. Remove bluetooth from the SupplementaryGroups= line in /etc/systemd/system/tattlestone-bridge.service, run daemon-reload, restart, and send me the error the app shows.
If you followed the old guide and created tattlestone-rfcomm.service or ran rfcomm bind, undo it. A bound rfcomm0 can hold the adapter:
sudo systemctl disable --now tattlestone-rfcomm; sudo rm -f /etc/systemd/system/tattlestone-rfcomm.service; sudo rfcomm release all

4 Test the bridge with nc UNO Q + Mac

On the board, leave this running:

journalctl -u tattlestone-bridge -f

In a new Mac terminal. The pause lets the bridge finish connecting, since anything sent before BRIDGE READY is dropped:

(sleep 8; printf 'ATI\r010C\r'; sleep 4) | nc 192.168.1.33 35000; echo
Expected:
BRIDGE STATUS: connecting to the OBD adapter
BRIDGE READY
then an ELM327 v1.x line and a 41 0C … (or NO DATA with the engine off), each ending in >. The journal shows Adapter link up and then Client disconnected (closed by app).

Retry lines such as OBDLink … not answering, retrying in 2s (attempt 1) are normal for the first few seconds after the ignition comes on.

5 Connect from Tattlestone, once Mac

  1. Rebuild the app from the same branch: cd files && npm run install:app. Check that Settings → About → Build shows fix/bridge-owns-bluetooth-link (or main after merge).
  2. Connection → Network → 192.168.1.33:35000 → Connect.
  3. Under "Connecting…" you'll see the bridge's progress, then Initialization complete. Protocol: SAE J1850 VPW in the log.
After this first successful connection the app remembers the bridge. From now on, opening the app connects by itself.

6 Check close and reopen Mac + UNO Q

  1. Quit Tattlestone (⌘Q). The journal on the board shows Client disconnected (closed by app).
  2. On the board, confirm the Bluetooth link was released (should print Connected: no): 
    bluetoothctl info "$(bluetoothctl devices Paired | grep -i obd | awk '{print $2}')" | grep Connected
  3. Open Tattlestone again. Don't click anything. It should connect within a few seconds and finish initialization.
  4. Repeat once more to be sure.

7 Check after a board reboot UNO Q + Mac

sudo reboot

Wait about a minute, then open Tattlestone. If the board is still booting, the app shows "Bridge … not reachable yet — retrying" and tries again after 3 s and 10 s. No rfcomm or other manual step should be needed.

8 Stop auto-connecting (optional) Mac

Click Disconnect in the Connection screen. The app forgets the bridge and won't connect on open until you connect manually again.
