Get the Wi-Fi bridge talking

Tattlestone ↔ Arduino UNO Q · next steps after the 2026-10-21 fix

What's going on

Nothing was running on the UNO Q, so Tattlestone's connections to 192.168.1.33:35000 were refused. The code is fixed and tested on the Mac. What's left is copying it to the board, starting it as a service so it survives reboots, and checking that data comes back.

You'll use the ELM327 emulator first. It answers like a real OBD adapter, so you can prove the Wi-Fi link works without the Bluetooth/OBD side.

1 Copy the bridge files to the board Mac terminal

From the Mac, run this. It asks for the arduino user's password.

scp -r ~/Tattlestone/agador-spartacus/files/firmware/uno-q-bridge arduino@tattlestone.local:/home/arduino/
Done when you see the files listed as they copy: obd_tcp_bridge.py, command_policy.json, elm327_emulator.py, the two .service files, tattlestone-bridge.env and the test file.
If tattlestone.local isn't found, use the IP instead: arduino@192.168.1.33:/home/arduino/

2 Install the services Board terminal

Open a shell on the UNO Q, the same way you ran ss earlier. First check that Python is where the service files expect it:

which python3

It should print /usr/bin/python3. If it prints something else, tell Claude before you go on.

Then install both service files:

sudo cp ~/uno-q-bridge/tattlestone-bridge.service ~/uno-q-bridge/tattlestone-emulator.service /etc/systemd/system/
sudo systemctl daemon-reload

Create the bridge's pairing token. It prints the token: copy it, you'll paste it into the app in step 6.

sudo python3 ~/uno-q-bridge/obd_tcp_bridge.py --new-token /etc/tattlestone/bridge-token
sudo chgrp arduino /etc/tattlestone/bridge-token
Lost it? sudo cat /etc/tattlestone/bridge-token shows it again. The real bridge won't start without this file. The emulator doesn't use it.

3 Start the emulator Board terminal

sudo systemctl enable --now tattlestone-emulator
systemctl status tattlestone-emulator --no-pager
ss -ltnp | grep 35000
Done when status says active (running) and ss shows 0.0.0.0:35000. enable means it also starts on every boot.
If ss shows 127.0.0.1:35000 instead, an old copy of the emulator is running by hand. Stop it with pkill -f elm327_emulator, then run sudo systemctl restart tattlestone-emulator.

4 Test the link by hand Mac terminal

Send one command over Wi-Fi and read the reply:

printf 'ATI\r010C\r' | nc -w 2 192.168.1.33 35000
Working: you see ELM327 v1.5, then a line starting with 410C, each followed by >.
If you see Connection refused, go back to step 3. If nothing prints at all, see the troubleshooting table below.

5 Rebuild and install the app Mac terminal

The installed Tattlestone.app is older than the source code, so rebuild it:

cd ~/Tattlestone/agador-spartacus/files
npm run install:app
Done when it finishes without errors and /Applications/Tattlestone.app has been replaced.

6 Connect from Tattlestone Tattlestone app

  1. Quit Tattlestone if it's open, then start it again.
  2. Open the Connection screen and choose Network.
  3. Enter 192.168.1.33:35000.
  4. Paste the pairing token from step 2 and click Save token (needed for the real bridge; the emulator ignores it).
  5. Click Connect over Wi-Fi.
  6. If macOS asks to let Tattlestone find devices on your local network, click Allow.
Working: the status goes to Connected, the adapter shows the emulator, and live values like RPM (around 820) appear.

Then export the session log from the app and send it to Claude. It should now contain RX … lines; that's the proof data is coming back.

If something goes wrong

The app's red banner now tells you which part failed:

Banner or result saysMeaningWhat to do
Nothing is listening on … [ECONNREFUSED]The board is up, but the service isn't runningOn the board: sudo systemctl restart tattlestone-emulator, then journalctl -u tattlestone-emulator -n 30
Can't reach … [EHOSTUNREACH]The board is off, still booting, or on another networkWait 30 s and retry. Check the Mac and the board are on the same Wi-Fi. Check System Settings → Privacy & Security → Local Network → Tattlestone is on
Can't find … [ENOTFOUND]The .local name didn't resolveType the IP address (192.168.1.33:35000) instead
Adapter not responding — no reply to ATZ/ATIConnected, but nothing answeredRun the step-4 nc test. If that works, send Claude the session log
BRIDGE ERROR: cannot open /dev/rfcomm0 in the logThe real bridge is running, but there's no OBD adapter on the boardExpected for now. Use the emulator (step 3)
… requires its pairing token [BRIDGE_AUTH_REQUIRED]No token saved for this addressPaste the token from /etc/tattlestone/bridge-token and click Save token
authentication failedThe saved token doesn't match the board'sCopy it again with sudo cat /etc/tattlestone/bridge-token, then Save token
The board's IP changedDHCP gave it a new addressOn the board: hostname -I, then use that IP everywhere above

Later: switch to the real OBD bridge

Do this once the Bluetooth/OBD side works and /dev/rfcomm0 exists on the board. On the board:

sudo systemctl disable --now tattlestone-emulator
sudo systemctl enable --now tattlestone-bridge
journalctl -u tattlestone-bridge -f

Only one can run at a time; they share port 35000. Note that if the Mac is connected to the OBDLink over Bluetooth, the board can't use it at the same time.
